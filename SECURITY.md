# Security policy

Familista holds club, player and performance data, some of it about children.
We want to hear about any weakness in it, and we will not take action against
anyone who reports one in good faith under the rules below.

## Reporting a vulnerability

Report privately through GitHub: **Security → Report a vulnerability** on this
repository (a private security advisory). Please do not open a public issue,
pull request or discussion for a security problem.

Include what you found, where (URL, endpoint or file), how to reproduce it, and
what an attacker could do with it. A minimal proof is enough — please do not
build a working exploit chain.

## What happens next

| Step | Target |
|---|---|
| Acknowledgement of your report | within 3 working days |
| First assessment (accepted, need more information, or not a vulnerability) | within 10 working days |
| Fix for a confirmed critical or high finding | within 30 days |
| Fix for a medium or low finding | in a scheduled release, usually within 90 days |

We will tell you when the fix ships and, if you wish, credit you in the
advisory.

## Rules for testing

- Test only against an account and a club you created yourself. Never access,
  change or delete another user's or club's data; if you reach some by
  accident, stop, do not keep a copy, and tell us.
- No denial of service, load testing, spam, social engineering, or physical
  attacks on people, devices or premises.
- Do not test third-party services Familista uses (Render, Stripe, SendGrid,
  Anthropic, Backblaze); report problems in them to their owners.
- Give us a reasonable time to fix a finding before telling anyone else about
  it.

## Scope

In scope: this repository's code and the Familista service it runs. Out of
scope: findings that need a compromised device or browser, missing security
headers with no demonstrated impact, rate limits on non-sensitive endpoints,
and reports generated by automated scanners without a confirmed impact.

## Supported versions

Only the current `main` branch, which is what production runs, receives
security fixes.

## How the platform is defended

The controls themselves are described under `docs/security/` and enforced in
CI by the security posture check (`npm run security:check`).
